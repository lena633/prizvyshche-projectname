# Інструкція для контриб'юторів (CONTRIBUTING.md)

## 1. Іменування гілок
- Для нових функцій: `feature/короткий-опис` (наприклад, `feature/title-normalizer`)
- For виправлення багів: `bugfix/короткий-опис`
- Для документації: `docs/короткий-опис`

## 2. Формат повідомлень комітів
Усі коміти мають слідувати стандарту Conventional Commits:
- `feat:` — додавання нового функціоналу.
- `fix:` — виправлення помилки.
- `docs:` — зміни в документації (README, CONTRIBUTING).
- `chore:` — рутинні завдання, налаштування конфігів.

## 3. Вимоги до Pull Request
- PR повинен створюватися за автоматичним шаблоном.
- Перед створенням обов'язково запустити `ruff check .` та `ruff format .`.
- Обов'язкове схвалення (Approve) щонайменше від одного рецензента перед злиттям у `main`.
